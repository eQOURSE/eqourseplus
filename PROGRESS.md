Last completed FR: FR-REG-01 — 2026-08-05 — Freelancer sign-up shipped in two sessions: API (`cee45f6`) then web (`65a0bd3`). `POST /api/v1/auth/register/request` and `POST /api/v1/auth/register/verify` use a dedicated registration service and store, leaving FR-FND-02’s login path untouched; tokens issue only after both the email and phone OTP verify. The `users` collection was extended per SPEC §19.2, with a migration creating sparse unique indexes on `phone` and `pan`. Explicit `null` defeats a sparse unique index: MongoDB skips a missing field but indexes a stored null, so logical nulls are persisted as omitted fields. Without that rule, every account without a PAN after the first would have been rejected as a duplicate. `MongooseAuthStore.rotateRefreshSession` was broken and unreachable by tests: it combined `$set` on `refreshSessions.$.revokedAt` with `$push` on `refreshSessions`, which MongoDB rejects as error 40, `ConflictingUpdateOperators`. It survived because `auth.e2e-spec.ts` runs against an in-memory fake store, leaving the real Mongo path uncovered. Measured rather than assumed: restoring the old implementation returns HTTP 500. Rotation now uses an aggregation-pipeline update and has real-Mongo coverage for rotation, reuse rejection, and failing closed when `revokedAt` is explicitly null. Duplicate phone and PAN values hard-block behind a field-agnostic 409 so the endpoint cannot reveal which field is registered; an unverified registration with expired OTPs is reclaimable so a stranger cannot permanently squat another person’s phone. A repeated device fingerprint raises a `DUPLICATE_DEVICE` review flag and never blocks. The fingerprint is a domain-separated HMAC over IP, user-agent and accept-language, and only its hash is persisted. It derives from `JWT_SECRET`, so rotating that secret resets every fingerprint. An `SmsAdapter` contract and sandbox implementation were added without selecting a provider or adding an external dependency. The web half is a two-step form at `/register/freelancer`, implemented as a client island inside a server component. The browser calls the API directly because a Next proxy would replace every user’s IP and user-agent with the web server’s identity, making every fingerprint identical. CORS uses an explicit origin allowlist, rejects `*`, and requires production configuration. The country list contains ISO 3166-1 alpha-2 codes rendered through `Intl.DisplayNames`; it populates after mount to prevent server/browser CLDR differences from causing hydration mismatches, and a test proves every code resolves to a name other than the code. Enabling the country selector made WCAG 2.1 SC 1.4.11 applicable, so form-control boundaries are scoped to `--primary`, measuring 3.76:1 in light mode and 4.69:1 in dark mode without changing global `--border`. `@eqourse/shared` is now a workspace dependency of `apps/web`, bringing zod into the registration bundle while remaining isolated from the SEO routes: `/`, `/freelancers`, `/vendors` and `/about` remain at 160 kB First Load JS, while `/register/freelancer` is 230 kB. 274 tests are green; lint and production build pass on CI’s pinned Node 22.23.1. Registration routes remain noindex and absent from the sitemap. The four public pages and their specs remain byte-identical to their pre-FR-PUB-06 state.
